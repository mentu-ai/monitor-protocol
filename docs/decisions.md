# Decisions (append-only)

| Date | Decision | Why | Source |
|---|---|---|---|
| 2026-09-21 | Adopt, do not invent: CloudEvents envelope, MCP as client door, Nostr filter grammar, Kafka/K8s delivery vocabulary; own only the five objects and the epistemic rules | the mechanics exist elsewhere and will be compared; the novelty is the epistemic layer | `prior-art.md`, `delivery-semantics.md` |
| 2026-09-21 | CloudEvents `id` stays the dedup key; ordering is the `sequence` extension, zero-padded to 20 digits | CE `sequence` is a String comparable only within a `source`; `id`+`source` is CE's dedup rule | `prior-art.md` §1 |
| 2026-09-21 | Per-monitor `sequence` must be strictly increasing, not dense | Atrio's log is one global sequence; a monitor sees a subsequence with gaps | `atrio-bus-map.md` §7 |
| 2026-09-21 | Reserve method prefixes `monitors/`, `feeds/`, `leases/`, `notifications/monitors/`; never `subscriptions/` or `tasks/` | MCP core owns `subscriptions/listen`; Tasks reserves `tasks/` | `prior-art.md` §4 |
| 2026-09-21 | Delivery is at-least-once with manual commit only; no auto-commit mode | Kafka's auto-commit default leaks toward at-most-once | `delivery-semantics.md` |
| 2026-09-21 | Wake-ups (MCP listen, Claude Code Monitor, webhooks) are best-effort and sit above the cursor; the cursor is the guarantee | MCP 2026-07-28 removed stream resumability and declares notifications best-effort | `prior-art.md` §4 |
| 2026-09-21 | `origin: agent` may never carry `tier: src` (`TIER_NOT_ASSERTABLE`), and a refusal is emitted as an observation | Atrio §10 and §9, paid for in the first live week | `00-principles.md` P1, P2 |
| 2026-09-21 | State lists missing inputs and gaps; `confidence.value` is `null` until every input is present | `?? 0` turns a missing measurement into a confident one (Subtrace scar 722) | P3 |
| 2026-09-21 | Monitor (definition) and Subscription (consumer) are separate objects | Atrio held both in one row; a second consumer of the same monitor was impossible | `atrio-bus-map.md` §7 |
| 2026-09-21 | A `monitors/publish` method exists for external producers | shell/webhook monitors need a write path; the spec had none | implementation of C04/C16 |
| 2026-09-21 | Lease vocabulary: Kubernetes Lease fields plus Kafka share-group outcomes (`release`, `reject`, `delivery_count_limit`) | both are current, primary-source vocabularies for exactly this | `delivery-semantics.md` |
| 2026-09-21 | Working names (`ai.mentu` vendor prefix, "Monitor Protocol") until the owner names the protocol and its public home | owner decision pending | intent §Open questions |
| 2026-09-21 | Timestamps carry milliseconds (RFC 3339 fractional seconds) | a deadline in seconds cannot be decided from a timestamp truncated to seconds: a 1 s lease expired early and a 1 s mute threshold never quite late. Found by conformance C19 against the reference server. | `spec/04-delivery.md`; reference server |
| 2026-09-21 | The top provenance tier is never reached by defaulting; `src` must be asserted explicitly | holding a monitor's token is not being a person. A machine publishing under a `human:` owner silently obtained `[SRC]`; found by the reference implementation's own test. | P1 |
| 2026-09-21 | An SSE stream ends on the response closing, never on the request stream ending | a bodyless GET's request stream ends immediately, which cut every stream off after its first batch. Found by the HTTP test. | `spec/03-bindings.md` |
| 2026-09-21 | Monitor ids match `[\w.-]{2,64}` | inherited from the first implementation; short ids collide with path segments and read as typos. | `spec/01-objects.md` |
| 2026-09-21 | The MCP extension id travels under `experimental` until an SDK carries `extensions` | the installed SDK's `ServerCapabilities` has no `extensions` field; the name in the spec is the one that matters. | `spec/03-bindings.md`, `docs/ARCHITECTURE.md` |
| 2026-09-21 | Every state change that a client was told succeeded is written to the snapshot before the reply | a committed cursor that does not survive a restart is not a commit. Found by a consumer test against the packed tarball: after a restart the subscription re-delivered everything it had acked. Ack, seek, token rotation and a delivery that advanced `deliveredMax` now persist; an empty long-poll iteration still writes nothing. | `spec/04-delivery.md`; reference server |
| 2026-09-21 | The CLI runs only when the module is the process entry point, and `prepare` builds on a git install | importing the library printed the CLI usage and set a non-zero exit code; a `github:` install shipped no `dist/` because it is gitignored. Both found by consumer tests before the first publish. | package |
| 2026-09-21 | The top of each provenance ladder needs an **attested** monitor: created against a registration token and owned by a `human:` principal | `origin` arrives in the same body as the claim it would justify, so it cannot authorise it. An audit published five inflations; only the one the conformance check sent was refused. An open server still works, it just cannot mint top-tier provenance. | P1, `spec/01-objects.md` |
| 2026-09-21 | The cursor is the **next seq to deliver**, inclusive, and the implementation moved to meet the spec rather than the other way round | Kafka's committed position is the next record to consume, and the spec said so twice. The server read it as last-delivered, so a client written from the prose lost one observation per batch, silently, forever. | `spec/04-delivery.md`, `src/store.ts` |
| 2026-09-21 | `head` is the monitor's own, and `lag` is what this subscription would receive if it pulled now, its filter included | A lag over a shared counter never reaches zero for a filtered subscriber, so "pull until lag is zero" does not terminate. Measured on a live board the same day: a correct client reported lag 104 and an observer read it as broken. | P5 |
| 2026-09-21 | A cursor that is not an integer is refused | `Number("abc")` is NaN and NaN fails every comparison, so the backwards guard passed, the cursor persisted as null, and the subscription went silent for good. | P3, P11 |
| 2026-09-21 | Capabilities are granted, not requested; `shared` mints a subscribe token | Anyone could ask for `act` on a public monitor and take the lease a worker needed, and `shared` was a synonym for world-readable. | P7, P14 |
| 2026-09-21 | The admin endpoints always require an admin token, and the snapshot is never anonymous | `GET /admin/snapshot` returned every private definition and every owner and subscription token hash to an unauthenticated caller, in exactly the mode the self-conformance run uses. | `spec/02-methods.md` |
| 2026-09-21 | Seven checks added (C22–C28) and C20b named in the checklist | A mutation experiment passed a server that stored the cursor and ignored it, a server with no authentication at all, and observations carrying values outside the vocabularies. A suite that cannot fail a wrong implementation is decorative. | `spec/05-conformance.md` |
| 2026-09-22 | `schemas/` is **normative for the shape of the objects as served**, and C29 validates every object a conformance run receives | The audit found nothing validating against them: seven files `$ref`'d by nothing, twenty disagreements between prose, schema and types, all live. A schema nobody enforces is a fourth opinion, not a contract. Requests stay a subset of the objects they create, so the schemas constrain responses, not request bodies. | `spec/01-objects.md`, `spec/05-conformance.md` |
| 2026-09-22 | The validator is written here, in both runners, and **fails closed on any keyword it does not implement** | A protocol package should not need a dependency to describe itself, and a validator that silently ignores a keyword reports "valid" for a schema it did not understand. Both runners cover the same subset; a schema that reaches for `allOf` or anything else unimplemented is an error, not a pass. | `src/schema.ts`, `conformance/python/run.py` |
| 2026-09-22 | The twenty prose/schema/type disagreements were reconciled by deciding a winner per row, not by loosening the schemas | Where the implementation was right the prose moved (`Observation.source` is `monitor:<id>`, `log` is a source kind, `INVALID` is one of the codes); where the prose was right the schema tightened (monitor id pattern, required sets, named `ages`, provenance required); where neither was, the field was cut back to what exists (`live.reason` is the two reasons an implementation can emit, not six). | annex in `docs/evidence/monitor-protocol-audit-2026-09-21/` |
| 2026-09-22 | `DEFAULT_TIER` / `DEFAULT_VERIFICATION` renamed to `ORIGIN_TIER_CEILING` / `ORIGIN_VERIFICATION_CEILING` | The exported table read `human → src`, which is true only for an attested monitor; a name that has to be read alongside a comment to avoid a security misreading is the wrong name. | `src/vocab.ts` |
| 2026-09-22 | `rules` are validated on write | P11 says every vocabulary is checked on write, and `rules[].then` was stored unchecked — a rule nobody can enforce, recorded as if it were policy. | `src/server/core.ts` |
| 2026-09-22 | An agent acts at the **access level of the monitor's owner** and names them in `on_behalf_of`; the registration-token gate is withdrawn | Trust starts from relationships that already exist, and the one that exists here is the monitor: a person owns it and hands its token to their agent. Requiring the agent to hold a credential of its own answers a social question with an administrative one and refuses the common case. `on_behalf_of` may name **only the owner**: the first draft let it name anyone, which made delegation a way to borrow a stranger's level and would have reopened the audit's inflation finding on every server that requires registration. C26's fifth probe is the one that tells the two drafts apart. | P1, `spec/01-objects.md`, C26 |
| 2026-09-22 | `attested` is a **disclosure**, not a gate: an unattested server is fully functional and every state it serves carries `unattested_origin` | Where the protocol cannot verify, it discloses. A gate that an open server cannot pass makes the open server useless and teaches operators to work around the field; a gap on every state makes the same fact legible to the reader who is deciding how far to lean on it. | P1, P3 |
| 2026-09-22 | A machine may carry a human origin **only when it names the person**, and the person must be the monitor's owner; the actor prefix stays a ceiling otherwise | The refusal is for a claim that contradicts itself — `agent:evil` alone asserting `human`, or naming someone the monitor does not act for — not for a claim the server cannot check. The server never knows who is at the keyboard; pretending otherwise was the heavier half of the first design. | P1, C26 |
| 2026-09-22 | The MCP `monitor_publish` tool advertises `on_behalf_of` | The tool's schema allowed extra properties, so the field reached the server, but a model reads the schema to decide what to send. A capability no client can discover is claimed, not wired. | `src/server/mcp.ts` |
| 2026-09-22 | `ATTESTED_ONLY` / `UNATTESTED_CEILING` renamed to `HUMAN_PRINCIPAL_ONLY` / `MACHINE_CEILING`, in both implementations | Attestation no longer gates anything, so the old names named the wrong condition — the same defect the `DEFAULT_TIER` rename fixed a day earlier. A constant whose name has to be read alongside a comment to avoid a security misreading is the wrong constant name. | `src/vocab.ts`, `children/atrio/mp.py` |
| 2026-09-22 | A release publishes the tarball CI built and tested, uploaded as an artifact, never a local rebuild | The bytes on the registry should be the bytes the suite passed. A local `npm publish` rebuilds `dist/` on whatever machine runs it; publishing the CI artifact removes that gap and needs no local build at all. | `.github/workflows/ci.yml` |
| 2026-09-22 | A leading `~` in `--state` is expanded to the home directory | A shell expands it; an MCP client's JSON configuration passes it through literally, and the server then created a folder named `~` wherever the client started it. Found while writing the documentation's MCP example, which would have taught readers the bug. | `src/paths.ts` |
